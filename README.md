# ntx-csg.org

Website for NTXCSG. Built with Next.js (App Router) and deployed on Vercel. Pushing to the `main` branch on GitHub automatically triggers a production build and deploy.

> Stack: Next.js (App Router) + TypeScript + pnpm + Tailwind, generated by v0. There's a `config/` directory, so content is config-driven, edit the config files rather than hardcoding into components where possible.

## How deployment works

The flow is: edit code locally, push to GitHub, Vercel builds and deploys automatically.

1. You push a commit to GitHub.
2. Vercel sees the push (via the GitHub integration) and starts a build.
3. Pushes to `main` deploy to **production** (`ntx-csg.org`).
4. Pushes to any other branch, or a pull request, get a **preview** deployment with its own temporary URL.

You do not run any deploy command manually. Git is the trigger.

## Prerequisites

- Node.js 18+ (check with `node -v`)
- Git
- Access to the GitHub repo
- A Vercel account with access to the project (for checking deployments)

## Making changes

Work on a branch, not directly on `main`, so you get a preview deploy to check before it goes live.

```bash
git checkout -b my-change
# edit files
pnpm dev        # verify locally
```

Before pushing, build locally to catch errors that would fail the Vercel build:

```bash
pnpm build
```

If `pnpm build` passes locally, it will almost always pass on Vercel. Make sure Vercel's project settings use pnpm as the install command (it auto-detects this from `pnpm-lock.yaml`, but if a build fails on install, that's the first thing to check). If it fails, fix it before pushing. This is the single biggest time-saver, a broken build on Vercel just leaves the last good version live and shows a failed deployment.

## Pushing changes

Commit and push:

```bash
git add .
git commit -m "describe what changed"
git push origin my-change
```

Then open a pull request on GitHub. Vercel will comment on the PR with a **preview URL**. Click it, verify the change looks right on the real deployed environment.

To go live, merge the PR into `main`. That push to `main` triggers the production deploy.

If you're pushing straight to production (small fixes, working solo):

```bash
git checkout main
git add .
git commit -m "describe what changed"
git push origin main
```

That deploys to `ntx-csg.org` within a minute or two.

## Checking Vercel deployments

Go to https://vercel.com/dashboard and open the project.

**Deployments tab** shows every build with its status:

- **Ready** (green): live / deployed successfully.
- **Building** (yellow): in progress.
- **Error** (red): build failed. The previous good deploy stays live.

Click any deployment to see:

- **Build Logs**: the full output. This is where you look when a build fails. Scroll to the first red error line, that's usually the real cause; everything after it is noise.
- **Source**: which commit and branch triggered it.
- **Preview / Visit**: opens that specific deployment's URL.

To confirm what's live in production: the deployment tagged **Production** with the **Current** label is what `ntx-csg.org` is serving.

## When a build fails

1. Open the failed deployment in Vercel, read Build Logs, find the first error.
2. Reproduce locally with `pnpm build`.
3. Fix, commit, push again. A new deployment kicks off automatically.

Common causes: a missing dependency (not committed to `package.json`), a TypeScript/lint error, or an environment variable that exists locally but wasn't added in Vercel.

## Environment variables

If the site uses any env vars (API keys, config), they live in **Vercel → Project → Settings → Environment Variables**, not just your local `.env`. Local `.env` files are gitignored and never pushed, so anything the site needs at build or runtime must also be set in Vercel, or the production build will behave differently from local.

After adding or changing an env var in Vercel, redeploy for it to take effect (Deployments → latest → Redeploy).

## Custom domain

The domain `ntx-csg.org` is managed under **Vercel → Project → Settings → Domains**. DNS records are hosted at Squarespace and must match what Vercel lists there. If the domain shows "Invalid Configuration," fix the DNS records at Squarespace to match Vercel's values, then hit Refresh.

```bash
pnpm install        # install dependencies

pnpm build      # production build (run before pushing)

```
